# Diagnostics by area

Logs and commands to see what is going on before changing anything. `$DOT` below is the repo
checkout (e.g. `~/dotfiles`; `DOT=$(dirname "$(dirname "$(readlink -f ~/.config/hypr)")")`).
Commands with `sudo` must be run by the user if you have no access to their machine: give them
the exact command.

## Machine facts (read, do not assume)

- Monitors: `hyprctl monitors all` (names, modes, scales, which GPU via the connector name).
- GPUs and drivers: `lspci -k | grep -A3 -Ei 'vga|3d|display'`; NVIDIA state:
  `cat /sys/bus/pci/devices/*/power/runtime_status` for the NVIDIA device (reading sysfs does not
  wake it; `nvidia-smi` does).
- Model and kernel: `hostnamectl`, `uname -r`, `cat /proc/cmdline`.
- Disks and root: `lsblk -f`, `findmnt /`, `sudo btrfs subvolume list /`.
- Audio devices: `aplay -l`, `wpctl status`. Cameras: `v4l2-ctl --list-devices`,
  `ls /dev/v4l/by-path/`.
- The user's notes, if present: `$DOT/private/MACHINE.md`.

## General

- Errors this boot: `journalctl -b -p 3 --no-pager` (`-b -1`: the previous boot).
- Failed units: `systemctl --failed` and `systemctl --user --failed`.
- Recent package changes: `grep -E 'upgraded|installed|removed' /var/log/pacman.log | tail -40`.
- Pending `.pacnew` files: `pacdiff -o` (or `find /etc -name '*.pacnew'`).
- Repo vs `/` (templates will differ by their placeholders):
  `cd $DOT/system && find . -type f | while read f; do cmp -s "$f" "/${f#./}" || echo "differs: /${f#./}"; done`
  (or run `./install.sh system`, which renders the templates and lists what changed before asking).
- Broken dotfile links:
  `cd $DOT && grep -vE '^#|^$' links.txt | while read p; do [ "$(readlink -f ~/$p)" = "$PWD/home/$p" ] || [ "$(readlink -f ~/$p)" = "$PWD/private/home/$p" ] || echo "wrong: ~/$p"; done`

## Hyprland (`home/.config/hypr/`, docs/HYPRLAND.md)

- Config errors: `hyprctl configerrors` (also in Settings → Personalization → Hyprland).
- Log: `$XDG_RUNTIME_DIR/hypr/*/hyprland.log` (current session:
  `ls -t $XDG_RUNTIME_DIR/hypr/ | head -1`).
- State: `hyprctl monitors`, `hyprctl devices`, `hyprctl clients`, `hyprctl binds`,
  `hyprctl getoption <section:option>`, `hyprctl version`, `hyprctl submap`.
- Modules: `hyprland.lua` only has `require("conf.…")`; each module is its own scope (an error in
  one does not take down the others). Generated ones (`theme.lua`, `shell-settings.lua`) are loaded
  with `pcall`.

## Quickshell shell (`home/.config/quickshell/`, docs/QUICKSHELL.md and its CLAUDE.md)

- Log of the running shell: `qs log` (`qs log -f` to follow). Restarting it from a terminal
  (`pkill -x qs; qs`) prints QML errors there.
- Restart: `pkill -x qs; hyprctl dispatch 'hl.dsp.exec_cmd("qs")'`.
- IPC (what each `IpcHandler` exposes): `qs ipc show`; e.g. `qs ipc call settings open wifi`,
  `qs ipc call lock test`, `qs ipc call osd brightness`.
- A component that fails to load leaves "Type X unavailable" in its user: the error is in X (or
  something X uses), not in the file that reports it.
- Saved settings: `~/.config/quickshell/settings.json` (written by `Config.qml`).
- Active theme: `~/.local/share/quickshell/theme/current.json`; regenerate the files:
  `~/.config/quickshell/scripts/theme.sh apply ~/.local/share/quickshell/theme/current.json`.
- Old data names: `~/.config/quickshell/scripts/migrate.sh` (runs on every shell start).
- Data scripts can be run by hand to see what a Settings page gets:
  `scripts/storage.sh disks`, `scripts/apps.sh installed`, `scripts/printers.sh status`,
  `scripts/fonts.sh installed`, `scripts/theme.sh list`.

## Launcher and menu (walker, elephant; docs/WALKER.md)

- `systemctl --user status walker elephant`, `journalctl --user -u walker -u elephant -b`.
- Restart: `walker-restart` (or `systemctl --user restart elephant walker`); after a crash loop,
  `systemctl --user reset-failed walker` first.
- The system menu: `~/.local/bin/menu` (`menu --all-entries` prints the full table, without the
  entries hidden in Settings → Personalization → QuickShell → Menu; `menu --entries` the filtered,
  translated one).
- Keybind list as the menu sees it: `menu-keybinds --print`.

## Login, lock and idle

- greetd (autologin): `journalctl -b -u greetd`, `/etc/greetd/config.toml`.
- Lock: `~/.local/bin/lock-screen` (the shell and, if it does not answer within 5 s, hyprlock);
  mark `$XDG_RUNTIME_DIR/qs-locked`; PAM in `/etc/pam.d/quickshell-lock` and
  `quickshell-lock-face`; PAM failures: `journalctl -b | grep -iE 'pam|faillock'`. Failed attempts:
  `faillock --user $USER` (reset: `faillock --user $USER --reset`).
- Idle: `~/.config/hypr/hypridle.conf` (generated by the shell), `pgrep -a hypridle`.
- Howdy: `sudo howdy test`, `sudo howdy list`, `journalctl -b | grep -i howdy`; camera path in
  `/etc/howdy/config.ini` (`device_path`) vs `ls /dev/v4l/by-path/`.
- Keyring locked? `busctl --user get-property org.freedesktop.secrets /org/freedesktop/secrets/collection/login org.freedesktop.Secret.Collection Locked`.

## Boot (Limine, UKI, Plymouth, Secure Boot; docs/SYSTEM.md)

- Options the kernel booted with: `cat /proc/cmdline`.
- Limine: `/boot/limine.conf` (the real one, with snapshots) vs `system/boot/limine.conf`
  (template).
- UKI: `/boot/EFI/Linux/arch-linux.efi`; rebuilt with `sudo mkinitcpio -P` (hooks in
  `/etc/mkinitcpio.conf`, options in `/etc/mkinitcpio.d/linux.preset`).
- Plymouth: disabled (`plymouth.enable=0`, `systemctl is-enabled plymouth-start.service` →
  `masked`). Did it start anyway? `journalctl -b | grep -i plymouth`. Theme in
  `/etc/plymouth/plymouthd.conf`; test without rebooting:
  `sudo plymouthd; sudo plymouth --show-splash; sleep 5; sudo plymouth quit`.
- External monitor black after boot: `cat /sys/class/drm/card*-*/status`, `hyprctl monitors`,
  `grep -iE '<monitor>|page-flip' "$XDG_RUNTIME_DIR/hypr/$(ls -t $XDG_RUNTIME_DIR/hypr/ | head -1)/hyprland.log" | tail`
  and `cat /proc/cmdline`. See docs/HARDWARE.md.
- See a boot's messages: `Esc` during the logo, or remove `quiet splash` in Limine (`E`).
- Timing: `systemd-analyze`, `systemd-analyze blame | head`, `systemd-analyze critical-chain`.
- Secure Boot: `sudo sbctl verify`, `sbctl status`; sign what sbctl already knows:
  `sudo sbctl sign-all`.

## Snapshots and updates

- `sudo snapper -c root list`, `/etc/snapper/configs/root` (`NUMBER_LIMIT=1`), `/etc/default/limine`.
- `arch-update` (`system/usr/local/bin/arch-update`), log `/var/log/arch-update.log`
  (`less -R`); from the shell, Settings → Updates; `arch-update --dry-run` shows the plan.
- Space in `/boot` (the UKI is ~170 MiB): `df -h /boot`.
- btrfs migration: `scripts/snapshots-setup.sh` (`phase1|phase2|phase3|cleanup`).

## Audio, displays and peripherals

- Audio: `wpctl status`, `wpctl inspect @DEFAULT_AUDIO_SINK@`, `pactl list short sinks`,
  `journalctl --user -u wireplumber -u pipewire -b`. G14-only patch: `/etc/modprobe.d/g14-audio.conf`
  and `/usr/lib/firmware/g14-audio.fw` (need `mkinitcpio -P` and a reboot; check with
  `journalctl -k -b | grep -E 'Mic=0x19|Mic=0x1b'`).
- Brightness: `~/.config/quickshell/scripts/brightness.sh get [monitor]`; backlights:
  `ls /sys/class/backlight/`; external via DDC/CI: `ddcutil detect` (`i2c` group, `i2c-dev`
  module).
- Monitors: `hyprctl monitors all`, `~/.config/hypr/conf/monitors.lua`.
- Network: `nmcli device status`, `nmcli connection show`, `resolvectl status`.
- Bluetooth: `bluetoothctl show`, `bluetoothctl devices`, `systemctl status bluetooth`.
- Printers: `lpstat -t`, `journalctl -b -u cups`, `~/.config/quickshell/scripts/printers.sh status`.
- Input (keyboard, mouse, touchpad): `hyprctl devices`; options in `conf/shell-settings.lua`
  (generated) and `conf/input.lua` (gestures, specific devices, per-app rules).
- Screen sharing: `systemctl --user status xdg-desktop-portal-hyprland`, `~/.config/hypr/xdph.conf`.
