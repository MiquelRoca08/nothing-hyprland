# Hyprland

Hyprland 0.56 with the configuration in **Lua** (`home/.config/hypr/`). Two monitors with different
scales: `eDP-1` (laptop, scale 1.8–2, AMD) and `DP-9` (27", scale 1, NVIDIA). Some files are
generated by the Quickshell shell ([QUICKSHELL.md](QUICKSHELL.md)); the launcher and the system
menu are in [WALKER.md](WALKER.md).

## Modular configuration

The monolithic `hyprland.lua` was split into modules, following the official guide (wiki → *Core →
Using Multiple Configuration Files*): `require("conf.xxx")`. Each `require` is its own scope, so an
error in one module does not stop the others from loading.

```
~/.config/hypr/
├── hyprland.lua        ← only the list of requires: everything that is loaded is here
├── conf/
│   ├── monitors.lua    eDP-1 and DP-9 (rewritten by Settings → Displays on apply; can be edited by hand)
│   ├── env.lua         environment (cursor: Win11-Fluent-Dark if installed, else XCursor-Pro-Dark; ~/.local/bin in PATH)
│   ├── autostart.lua   bloquear (the shell's lock screen), qs, hypridle, walker/elephant, steam, rog-control-center, discord
│   ├── permissions.lua
│   ├── look-and-feel.lua  borders, shadows, animations
│   ├── tema.lua        GENERATED by the theme (quickshell/scripts/tema.sh; not in git; `pcall(require)`): border colors
│   ├── shell-settings.lua  GENERATED by the shell on startup (not in git; `pcall(require)`): gaps, rounding and every input option (do not edit)
│   ├── layouts.lua     dwindle, master, scrolling
│   ├── misc.lua        no Hyprland wallpaper or logo; black background until the shell draws; restore the lock if the shell crashes
│   ├── input.lua       gestures, a Logitech M705 mouse and a CS2 scroll rule (everything else is in shell-settings.lua)
│   ├── xwayland.lua    X11 app scaling
│   ├── programs.lua    terminal (alacritty), file manager (nautilus), launcher (walker-launch)
│   ├── keybinds.lua    keybinds (each with a description) and the «menu» submap
│   └── rules.lua       window and layer rules (Settings, menu terminal, TUIs, walker without animation)
├── xdph.conf.plantilla screen-capture portal: the shell's screen-share picker (`compartir-pantalla`); install.sh generates xdph.conf with your $HOME
├── hyprlock.conf       fallback only: the lock screen belongs to the shell (if it does not answer, `bloquear` uses hyprlock)
└── hypridle.conf       GENERATED by the shell on startup (not in git; Settings → Lock): lock, screens off and suspend
```

- In Hyprland 0.56 dispatchers are written in Lua too: `hyprctl dispatch 'hl.dsp.exec_cmd("qs")'`. The classic syntax (`dispatch workspace 1`) is an error.
- **Fix in `input.lua`:** the CS2 scroll rule used `o.window(...)`, an Omarchy helper that does not exist here and stopped the rest of the file from loading. It is now `hl.window_rule({ match = { class = "cs2" }, scroll_mouse = 0.6 })`. A duplicated 3-finger gesture was also removed.

## Keybinds

**Careful when trying dispatchers by hand:** `hl.dsp.window.fullscreen(…)`, `cycle_next(…)`, `bring_to_top(…)` and similar ones, given arguments they do not understand (or none), **do not fail: they act on the active window**. To learn the format, try a value of a valid type but made up (e.g. `{ mode = "nada" }` answers «expected fullscreen/maximized»). `ALT+TAB` uses a Lua function as the bind's action (`cycle_next` + `bring_to_top`).

Every `hl.bind` in `conf/keybinds.lua` carries `{ description = "…" }`: the Lua API accepts it and it shows up in `hyprctl binds -j`, which is where `menu-atajos` reads the list from (without a description, a Lua bind only shows as `__lua` + a number). Settings → Keybinds edits them.

| Keybind | Action |
|---|---|
| `SUPER+SPACE` | system menu (`menu`) |
| `SUPER+ALT+SPACE` | walker (apps) |
| `SUPER+K` | keybind list (`menu-atajos`) |
| `SUPER+V` | clipboard history (walker) |
| `SUPER+CTRL+E` | emoji and symbols (walker) |
| `SUPER+CTRL+O` | Actions menu (screenshot, record, Do Not Disturb, idle lock, laptop screen) |
| `Print` / `SUPER+CTRL+C` | screenshot menu |
| `SHIFT+Print` / `SUPER+SHIFT+S` | capture a region |
| `ALT+Print` | record the screen (or stop) |
| `SUPER+ENTER` / `SUPER+Q` | terminal |
| `SUPER+W` | close window |
| `SUPER+T` | floating/tiled |
| `SUPER+SHIFT+F` | file manager |
| `SUPER+I` | Settings |
| `SUPER+ESCAPE` | the menu's «System» submenu (lock, suspend, log out, reboot, power off) |
| `SUPER+F` | fullscreen |
| `SUPER+TAB` / `SUPER+SHIFT+TAB` | next / previous workspace (with windows) |
| `ALT+TAB` | next window on the workspace (raised if floating) |
| Brightness keys | brightness of the **focused** monitor (`brillo.sh`) + OSD |
| Mic mute key | mute the default microphone + OSD |

`SUPER+SHIFT+S` no longer moves the window to the special workspace: it captures a region, like Win+Shift+S. `SUPER+S` still shows / hides that workspace; to move a window out of it, `SUPER+SHIFT+<number>`.

## X11 app scaling (Steam) with two monitors

- **Problem:** with `force_zero_scaling = true` (the illogical-impulse default), XWayland apps were tiny on the scale-2 panel.
- **Final setup** (`conf/xwayland.lua`): `force_zero_scaling = false` and `use_nearest_neighbor = false`. They have a sensible size on both monitors, slightly soft on the laptop panel.
- **Tried and dropped:**
  - `STEAM_FORCE_DESKTOPUI_SCALING`: the current client ignores it.
  - `-forcedesktopscaling`: only integers; 1.5 or 1.8 become 1.
  - Scaling depending on the monitor at launch, or an automatic restart when moving monitors: it worked, but the simple option was preferred.
- **Spotify:** native Wayland through `~/.config/spotify-launcher.conf` (`--ozone-platform=wayland`), so it is sharp and well scaled on both monitors.
