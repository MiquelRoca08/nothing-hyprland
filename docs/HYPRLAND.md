# Hyprland

Hyprland 0.56 with the configuration in **Lua** (`home/.config/hypr/`, linked to
`~/.config/hypr`). Some files are generated by the Quickshell shell ([QUICKSHELL.md](QUICKSHELL.md));
the launcher and the system menu are in [WALKER.md](WALKER.md). The monitor layout that ships is
the reference laptop's: see [HARDWARE.md](HARDWARE.md) and set yours in Settings → Displays.

## Modular configuration

`hyprland.lua` only lists the modules it loads, following the official guide (wiki → *Core →
Using Multiple Configuration Files*): `require("conf.xxx")`. Each `require` is its own scope, so
an error in one module does not stop the others from loading. Generated modules are loaded with
`pcall(require, …)` so a missing file is not an error.

```
~/.config/hypr/
├── hyprland.lua          only the list of requires: everything that is loaded is here (and a fallback monitor rule if monitors.lua is missing)
├── conf/
│   ├── monitors.lua      YOURS (not in git): monitor layout. Created by install.sh (links) from your previous config or the running session; rewritten by Settings → Displays on apply; can be edited by hand
│   ├── env.lua           environment: cursor (Win11-Fluent-Dark if installed, else XCursor-Pro-Dark), ~/.local/bin in PATH
│   ├── autostart.lua     lock-screen (the shell's lock), qs, hypridle, walker/elephant, and then your own apps from autostart-local.lua
│   ├── autostart-local.lua YOURS (not in git, optional): `return { "command", … }`, your own autostart apps; install.sh imports them from your previous config
│   ├── permissions.lua
│   ├── look-and-feel.lua borders, shadows, animations
│   ├── theme.lua         GENERATED by the theme (quickshell/scripts/theme.sh; not in git): border colours
│   ├── layouts.lua       dwindle, master, scrolling
│   ├── misc.lua          no Hyprland wallpaper or logo; black background until the shell draws; lock restore if the shell crashes
│   ├── input.lua         gestures, specific devices and per-app rules (general input options are in shell-settings.lua)
│   ├── shell-settings.lua GENERATED by the shell on startup (not in git): gaps, rounding and every keyboard/mouse/touchpad option
│   ├── xwayland.lua      X11 app scaling
│   ├── keybinds.lua      keybinds (each with a description), the «menu» and «capture» submaps; loads programs.lua
│   ├── programs.lua      terminal (alacritty), file manager (nautilus), launcher (walker-launch)
│   └── rules.lua         window and layer rules (Settings, menu terminal, TUIs, walker without animation)
├── xdph.conf.template    screen-capture portal: the shell's screen-share picker (share-picker); the installer generates xdph.conf with your $HOME
├── hyprlock.conf         fallback only: the lock screen belongs to the shell (lock-screen uses hyprlock if the shell does not answer)
└── hypridle.conf         GENERATED by the shell on startup (not in git; Settings → Lock screen): lock, screens off and suspend
```

**After a `git pull`** the repo's `post-merge` hook (`.githooks/`, enabled by `./install.sh links`
with `git config core.hooksPath .githooks`) runs `hyprctl reload` if the pull changed
`home/.config/hypr`. git replaces files by deleting and rewriting them, and Hyprland's automatic
reload can land in between: it finds no `hyprland.lua` and falls into emergency mode (no keybinds,
«cannot open …/hyprland.lua»), and does not reload again by itself. By hand: `hyprctl reload`.

Do not edit the generated files: change the setting in Settings (or the theme) instead. Settings →
Personalization → Hyprland shows `hyprctl configerrors`, every loaded module in order and opens
any of them in nvim.

### Lua syntax notes

- Everything is Lua: `hl.config({...})`, `hl.bind(...)`, `hl.window_rule({...})`,
  `hl.monitor({...})`, `hl.define_submap(...)`.
- Dispatchers are Lua too, also from the command line:
  `hyprctl dispatch 'hl.dsp.exec_cmd("qs")'`. The classic syntax (`hyprctl dispatch workspace 1`)
  is an error.
- Hyprland reloads by itself when a file is saved; `hyprctl configerrors` should print nothing.
- **Careful when trying dispatchers by hand:** `hl.dsp.window.fullscreen(…)`, `cycle_next(…)`,
  `bring_to_top(…)` and similar ones, given arguments they do not understand (or none), **do not
  fail: they act on the active window**. To learn a format, pass a value of the right type but
  made up (e.g. `{ mode = "nothing" }` answers «expected fullscreen/maximized»).
- Only use helpers that exist here: code copied from other setups (e.g. Omarchy's `o.window(...)`)
  stops the rest of the module from loading.

## Keybinds

Every `hl.bind` in `conf/keybinds.lua` carries `{ description = "…" }` (in English; translated
where it is shown). The Lua API accepts it and it shows up in `hyprctl binds -j`, which is where
`menu-keybinds` and Settings → Keybinds read the list from; without a description, a Lua bind only
shows as `__lua` + a number. The `-- ## …` comments are the group headings.

Settings → System → Keybinds edits them: "Change" captures a new combination and rewrites that
`hl.bind` in place. While it captures, Hyprland is in the empty **`capture`** submap (defined at the
end of `keybinds.lua`) so the combination reaches Settings instead of running; Escape or 10 s of
inactivity cancels.

| Keybind | Action |
|---|---|
| `SUPER+SPACE` | system menu (`menu`); pressed again, closes any open menu |
| `SUPER+ALT+SPACE` | walker (apps) |
| `SUPER+K` | keybind list (`menu-keybinds`) |
| `SUPER+V` | clipboard history (walker) |
| `SUPER+CTRL+E` | emoji and symbols (walker) |
| `SUPER+CTRL+O` | Actions menu (screenshot, record, Do Not Disturb, idle lock, laptop screen) |
| `Print` / `SUPER+CTRL+C` | screenshot menu |
| `SHIFT+Print` / `SUPER+SHIFT+S` | capture a region (like Win+Shift+S) |
| `ALT+Print` | record menu (or stop the recording) |
| `SUPER+ENTER` / `SUPER+Q` | terminal |
| `SUPER+W` | close window |
| `SUPER+M` | log out |
| `SUPER+T` | floating / tiled |
| `SUPER+J` | toggle the split direction (dwindle) |
| `SUPER+F` | fullscreen |
| `SUPER+SHIFT+F` | file manager |
| `SUPER+I` | Settings |
| `SUPER+ESCAPE` | the menu's «System» submenu (lock, suspend, log out, reboot, power off) |
| `SUPER+arrows` | move focus |
| `SUPER+1…0` / `SUPER+SHIFT+1…0` | go to / move the window to a workspace |
| `SUPER+S` | show / hide the special workspace (move a window out with `SUPER+SHIFT+<number>`) |
| `SUPER+TAB` / `SUPER+SHIFT+TAB`, `SUPER+wheel` | next / previous workspace (with windows) |
| `ALT+TAB` | next window on the workspace (raised if floating) |
| `SUPER+left drag` / `SUPER+right drag` | move / resize a window |
| Volume, mic mute, media keys | `wpctl` / `playerctl`, with the shell's OSD |
| Brightness keys | brightness of the **focused** monitor (`brightness.sh`) + OSD |

`ALT+TAB` uses a Lua function as the bind's action (`cycle_next` + `bring_to_top`).

### The `menu` submap

While a system menu is open, `~/.local/bin/menu` switches Hyprland to the `menu` submap, where
Backspace runs `menu-back` (go back one level) and everything else keeps working. `SUPER+SPACE` has
`submap_universal = true` so it also works inside it. See [WALKER.md](WALKER.md#system-menu).

## X11 app scaling

- `conf/xwayland.lua`: `force_zero_scaling = false` and `use_nearest_neighbor = false`. XWayland
  apps (Steam…) get a sensible size on monitors with different scales, upscaled with bilinear
  filtering (slightly soft on a HiDPI panel).
- Why not `force_zero_scaling = true` (a common default): X11 apps become tiny on a scale-2
  screen. Steam's own scaling options do not help: `STEAM_FORCE_DESKTOPUI_SCALING` is ignored by the
  current client and `-forcedesktopscaling` only takes integers.
- Prefer native Wayland where the app supports it: Spotify runs with `--ozone-platform=wayland`
  (`~/.config/spotify-launcher.conf`).
