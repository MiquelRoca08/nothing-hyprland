# Walker: launcher and system menu

A launcher ([walker](https://github.com/abenz1267/walker) + elephant) and a system menu modelled on
[Omarchy](https://github.com/basecamp/omarchy) 3.8.4, with the look of the shell's Settings window.

Files: `home/.config/walker/`, `home/.config/elephant/`, `home/.config/systemd/user/`
(`walker.service`, `elephant.service`), the scripts in `home/.local/bin/` and the pacman hook
`system/etc/pacman.d/hooks/walker-restart.hook`. Keybinds: [HYPRLAND.md](HYPRLAND.md#keybinds).

## Launcher

- **Packages** (AUR, `packages-aur.txt`): `walker` and `elephant-bin` plus the `elephant-*-bin`
  providers (desktopapplications, calc, clipboard, files, runner, symbols, unicode, websearch,
  providerlist, menus, windows, bookmarks, todo, bluetooth, playerctl, wireplumber, snippets).
  Without the providers walker shows "No Results". Not `elephant-archlinuxpkgs-bin`: nothing used
  it (packages are installed from the menu, with fzf) and it rewrote a ~90 MB cache on every elephant
  start (~740 MB peak memory, ~1 s startup). walker comes from the AUR: reinstall it
  with `yay -S walker`, not `pacman -S`.
- **User services** (enabled by the `appearance` installer module): `elephant.service` and
  `walker.service` (`walker --gapplication-service`, so it opens instantly), with `Restart=always`
  and `GSK_RENDERER=ngl` (GTK's OpenGL renderer; `cairo` leaves stray pixels from the previous frame
  when results change).
- **Without uwsm:** if you log in with the plain "Hyprland" session instead of the uwsm one,
  `graphical-session.target` is not reached and the services do not start, so
  `conf/autostart.lua` also starts them (a no-op if they are running). greetd starts the uwsm
  session.
- **PATH:** `conf/env.lua` adds `~/.local/bin` to Hyprland's `PATH` (without repeating it on
  reload) and `conf/autostart.lua` passes it to the services with `import-environment`: walker
  needs it for the menus and the emergency entry.
- **Config:** `~/.config/walker/config.toml.template` is the one to edit: `walker-config` writes
  `config.toml` from it (not in git) with its `@…@` texts ("Search…", "No results", "Restart
  walker") in the interface language, every time `walker.service` starts (`ExecStartPre`), since
  walker's config has no translations and is read once. It only holds what differs from
  `/etc/xdg/walker/config.toml` (walker merges them): fixed focus, wrap-around selection, no hint
  bar, no F1–F4, emoji as a list, 256 results and a "Restart walker" emergency entry. Prefixes are
  walker's: `;` providers, `>` runner, `/` files, `.` symbols, `!` todo, `%` bookmarks,
  `=` calculator, `@` web, `:` clipboard, `$` windows.
- **elephant** (`~/.config/elephant/`): `calc.toml` (no async), `desktopapplications.toml` (name
  only, no actions or history) and `symbols.toml`, which pastes the chosen emoji into the active
  window with `hyprctl dispatch 'hl.dsp.send_shortcut({ mods = "SHIFT", key = "Insert", window = "activewindow" })'`.
- **Scripts:** `walker-launch` starts the services if needed and opens walker (used by
  `SUPER+ALT+SPACE`, `SUPER+V`, `SUPER+CTRL+E`); `walker-restart` restarts elephant and walker,
  also as root from the pacman hook (through `systemd-run --uid`).
- **Pacman hook** `/etc/pacman.d/hooks/walker-restart.hook` (template in `system/`): after
  upgrading `walker` or `elephant*` it runs `walker-restart` for your user.

## Theme

`~/.config/walker/themes/nothing/`: Omarchy's `layout.xml` (644 px wide, one column) styled like the
shell's Settings window: a black panel with a 1 px border and radius 14, a search field like
Settings' fields (red border when focused), rows of **exactly 44 px** (`min-height` on `.item-box`,
the subtitle hidden with `opacity: 0` and 1 px, since `font-size: 0` can be treated as the default
size), the selected row like the current Settings page (tinted background, a 3 px red mark on the
left, bold white text), a thin scrollbar and icons in colour. Colours: `colors.css` holds the
Nothing palette and `theme.css` the active theme's, with every token of `Theme.qml` in snake_case
(`bg_alt`, `control`, `fg_soft`, `sel`, `sel_soft`…), generated by `quickshell/scripts/theme.sh`.
`conf/rules.lua` disables the animation of the `walker` layer.

## System menu

`~/.local/bin/menu` (≈ `omarchy-menu`), on `SUPER+SPACE`.

- **Main menu:** regular walker with the `menu` provider set (`[providers.sets.menu]` in
  `config.toml`). Without typing it shows the sections (elephant Lua menu `menus/system.lua`);
  typing searches **every** entry of every submenu, shown with its path ("Actions › Screenshot ›
  Region", `menus/systemsearch.lua`), plus the apps.
- **Sections:** Apps, Learn (keybinds and wikis), Actions (Screenshot, Record, Do Not Disturb, idle
  lock, laptop screen), Style (Wallpaper, Appearance), Settings (opens the shell's Settings), Install
  (Package, AUR, Flatpak, WebApp, TUI), Remove (Package, Flatpak, WebApp, TUI), Update (whole
  system, repos only, firmware, restart walker or the shell), About (`fastfetch`) and System (lock,
  suspend, log out, reboot, power off).
- **One table:** every entry is a line of `ENTRIES` in the script (`path|icon|text|target`). Both
  `.lua` menus read it through `menu --entries` (translated); `menu --all-entries` prints it in
  English without hiding anything (used by Settings → Menu). To add an entry: a line in `ENTRIES`,
  its case in `run`, and its Spanish in `~/.config/quickshell/i18n/es.js`.
- **Cached menus:** the `.lua` menus (`system`, `systemsearch`, `wallpapers`) use `Cache = true`
  with `RefreshOnChange`: elephant runs `GetEntries` again only when a watched **folder** changes
  (the script's real folder in the repo, `~/.config/quickshell` for `settings.json`, `i18n/`,
  `/etc` for `locale.conf`, `/var/lib/pacman/local` for installed programs, `~/Pictures/Wallpapers`).
  With `Cache = false` elephant calls `GetEntries` on **every keystroke**. Folders, not files: a file
  watch is lost after the first atomic save (rename), so later changes would not show.
- **`menu --entries` must stay cheap** (~30 ms): no `$(…)` per entry (translations read `I18N`
  directly, one `jq` for the three `settings.json` lists).
- **Commands:** `menu <path>` opens a submenu directly (e.g. `menu actions`, `menu screenshot`,
  `menu system`; Escape closes); `menu run <id>` runs an entry; `menu --from-main <path>` opens a
  submenu from the main menu (Escape goes back to it).
- **Entries that need a program** (`REQUIRES` in `menu`) are left out when it is missing: Record
  (`gpu-screen-recorder`, the whole submenu), Text (OCR) (`tesseract`), Install/Remove → Flatpak
  (`flatpak`) and Update → Firmware (`fwupdmgr`), everywhere: submenus, search and Settings → Menu.
  Opening a missing submenu directly (`menu record`, `ALT+Print`) and the `record` /
  `screenshot text` keybinds show a notification instead.
- **Customizable** from Settings → Personalization → QuickShell → Menu: hidden entries, section
  order and custom entries (icon, name, command, section), saved in `settings.json` (`menuHidden`,
  `menuOrder`, `menuCustom`) and read with `jq` by `menu` (the cached menus refresh when it
  changes). The English paths are the identifiers.
- **Submenus** are walker in `--dmenu` mode, without a search field. **Backspace goes back** like
  Escape: while a menu is open, `menu` switches Hyprland to the `menu` submap, where Backspace runs
  `menu-back`; it returns to `reset` when the menu closes. (Backspace cannot go in walker's own
  `close` key: it would close even with text typed.)
- **`SUPER+SPACE` with a menu open closes it**, from a submenu too: the bind has
  `submap_universal = true`, and the second `menu` leaves `$XDG_RUNTIME_DIR/menu-close` before
  `walker --close`; the first one sees it and exits.
- Width comes from the longest text (≈10 px per character + 100, minimum 295 px); the main menu's
  height is sections × 44 px + 6 px of slack (so fractional scales cannot clip the last row).
- Package tools and About run in a floating terminal of class `menu-terminal`.
- **Helpers:** `menu-keybinds` (keybind list from `hyprctl binds -j`; `--print` prints it),
  `menu-input` (ask for a text) and `menu-select` (pick an option), all with walker `--dmenu`.

## Tools used by the menu

| Command | What it does |
|---|---|
| `screenshot screen\|region\|window\|text` | Freezes the screen (`hyprpicker -r -z`), selects with `slurp`, saves to `~/Pictures/Screenshots` and copies to the clipboard; the notification opens `satty` to annotate. `text` runs the region through `tesseract` (English plus any other installed `tesseract-data-<lang>`) and copies the text. Pressing the bind again while selecting cancels |
| `record [--audio] [--mic]` / `record --stop` | `gpu-screen-recorder` of a monitor or region to `~/Videos/Recordings`; on stop, a notification with a thumbnail |
| `packages repos\|aur\|flatpak\|remove\|remove-flatpak` | Install/remove with an `fzf` list and the description below (`alt-p` hides it; in the AUR, `alt-b` shows the PKGBUILD); Tab marks several. Flatpak installs system-wide from Flathub; removing also deletes unused runtimes. Removal only lists explicitly installed packages |
| `webapp create\|remove\|open <url>` | A website in its own window with a launcher: asks for a name and URL, downloads the favicon, creates `~/.local/share/applications/<name>.desktop` (marked `X-Created-By=webapp`). Opens with `--app=` of your default browser if it is Chromium-based, otherwise with chromium (Firefox has no app mode) |
| `tui create\|remove` | A terminal program with a launcher: name, command, floating or tiled, optional icon; opens `alacritty --class TUI.float\|TUI.tile -e <command>` (`TUI.float` is floating, centred and 875×600 via `conf/rules.lua`). Marked `X-Created-By=tui` |
| Wallpaper | Elephant menu `menus/wallpapers.lua` (`walker-launch -m menus:wallpapers`) with the images in `~/Pictures/Wallpapers` and a preview; applies with `qs ipc call wallpaper set <path>` or `dots` |
| Laptop screen | `hyprctl dispatch 'hl.dsp.dpms({ action = "toggle", monitor = "eDP-1" })'` |
| Update | `~/.config/quickshell/scripts/update.sh` → `sudo arch-update --menu` in the floating terminal ([SYSTEM.md](SYSTEM.md#arch-update)) |

Web app and TUI launchers made by older versions of these scripts still work.

## Pitfalls

- If walker gets a `-s <set>` that is not in its config (e.g. it was not restarted after adding
  one), **it crashes** ("can't find specified set") and systemd stops restarting it; another walker
  may also hold the D-Bus name (`Unable to acquire bus name 'dev.benz.walker'`). Fix: kill the
  `walker` processes that are not `--gapplication-service`, then
  `systemctl --user reset-failed walker && systemctl --user start walker` (or `walker-restart`).
- `hl.dsp.send_shortcut(…)` **really pastes** the clipboard into the active window: do not try it
  by hand.
- `wtype -k <key>` reaches walker but **does not trigger Hyprland binds**: to test a bind, run its
  command.
- walker windows **grab the keyboard**: a test window opened while someone types steals the text.
- Opening walker right after closing another (≈0.5 s) sometimes does not show it; `menu --from-main`
  waits 0.3 s.
- A Lua menu **does not keep its globals** between calls: caching in a Lua variable does nothing;
  use `Cache = true` + `RefreshOnChange`.
- `pkill -f <text>` also kills the command that contains that text: close windows by PID
  (`hyprctl clients -j`).

## Design decisions

To compare with the reference, clone Omarchy v3.8.4
(`git clone --depth 1 --branch v3.8.4 https://github.com/basecamp/omarchy`) and read
`config/walker/`, `config/elephant/`, `default/walker/themes/`, `bin/omarchy-menu*`,
`bin/omarchy-capture-*`, `bin/omarchy-pkg-*`, `bin/omarchy-webapp-*` and `bin/omarchy-tui-*`.

| Topic | Decision |
|---|---|
| Look | Same design as the Settings window, icons in colour, no hint bar |
| Prefixes | walker's, not Omarchy's |
| Main menu | `SUPER+SPACE`, searching apps and every entry; `SUPER+ALT+SPACE` opens only the apps |
| Submenus | No search field; Backspace and Escape go back; `SUPER+SPACE` closes |
| Settings entry | Opens the shell's Settings window |
| Log out | `hyprctl dispatch 'hl.dsp.exit()'` (or `hyprshutdown` if installed) |
| Packages | fzf in a floating terminal, like Omarchy, plus Flatpak |
| Updates | `arch-update`, in the style of Omarchy 4.0; aborts if the snapshot fails |
